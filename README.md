# Assistant Craft Tool

An 8-step bilingual (NL/EN) wizard that turns a structured briefing into a
ready-to-paste AI assistant system prompt, with every submission logged to
MySQL for later analysis.

Originally generated by Lovable and rebuilt here on a production-friendly
stack that targets **Combell Node.js hosting** out of the box.

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Framework | **Next.js 15 (App Router)** | Unified TypeScript full-stack; Route Handlers for the API, server components for `/admin`. Runs on any Combell Node.js plan (Basic → Expert). |
| UI | **React 19 + Tailwind CSS v4** | Same React ecosystem as the original Lovable build; Tailwind v4 ships CSS-first design tokens that cleanly port the original palette. |
| Validation | **Zod** | One schema validates the form on the client and the payload on the server. |
| ORM | **Drizzle ORM + mysql2** | Type-safe queries; tiny runtime; first-class MySQL support. |
| Database | **MySQL 8** on the Combell Linux account | Combell's standard DB offering, reachable from the nested Node.js account. |
| Auth | **HTTP Basic Auth** via `src/middleware.ts` | Gates `/admin` and `/api/admin/*` without pulling in a full auth stack. |

## Quick start (local)

```bash
# 1. Install
npm install

# 2. Configure env vars
cp .env.example .env.local
# Edit .env.local — point DB_* to a local MySQL, and set ADMIN_PASSWORD.

# 3. Create the schema (either option works)
mysql -u root -p < src/drizzle/migrations/0000_create_submissions.sql
# or:
npm run db:migrate

# 4. Run the app
npm run dev
# → open http://localhost:3000       (the wizard)
# → open http://localhost:3000/admin (HTTP Basic Auth prompt)
```

### Don't have MySQL locally?

Simplest option with Docker:

```bash
docker run --name act-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root \
  -e MYSQL_DATABASE=assistant_craft \
  -d mysql:8
```

Then set in `.env.local`:

```
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=root
DB_NAME=assistant_craft
```

npm ci

## How submission logging works

1. User completes the wizard and clicks **Generate instruction**.
2. `OutputScreen` renders and, on mount, POSTs the full payload to
   `/api/submissions`:
   - `language` (`"nl" | "en"`)
   - `data` (the entire wizard form — the Zod-validated object)
   - `generatedPrompt` (the Markdown system instruction)
   - `kickoffMessage` (optional)
3. The route handler:
   - re-validates the payload with the **same** Zod schema
   - rejects submissions that don't meet the minimum quality bar
     (at least one of: domain / customDomain / jobTitle / assistantName)
   - hashes the requester's IP (first 16 bytes of SHA-256) for abuse
     triage without storing raw IPs
   - inserts a row into `submissions`
4. The user sees a confirmation toast. The admin can view/export from
   `/admin`.

## Extending

- **Add fields** → edit `src/lib/wizardSchema.ts` + translations +
  relevant step component. The JSON `data` column survives unknown fields,
  so no migration is required for additive changes. If you want dedicated
  columns, add them to `src/drizzle/schema.ts` and generate a migration.
- **Replace Basic Auth with a real login** → swap `src/middleware.ts`
  for NextAuth/Auth.js. Everything else stays the same.
- **Send an email on each submission** → add a `fetch("https://…")` call
  (e.g. Resend, Postmark) inside the try block of
  `src/app/api/submissions/route.ts`, after the successful insert.
